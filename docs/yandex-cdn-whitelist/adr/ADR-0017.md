# ADR-0017 — scoped immutable rollback

Status: proposed. Target-only; no deployment, audit result, measurement, or operational completion is claimed.

## Topic-specific target
scoped immutable rollback

## Problem
Choose a safe target for scoped immutable rollback without coupling it to ordinary VPN or claiming unobserved behavior.

## Constraints
The decision remains isolated, reversible, secret-free, and blocked from live use until its own evidence and same-turn approval gate exist.

## Alternatives
full restore versus manual repair versus scoped rollback point.

## Trade-offs
rollback catalog requires rehearsal; this cost is accepted only if the isolation boundary is demonstrated.

## Risks
stale pointer can select an invalid dependency; the risk remains an open blocker rather than an assumed success.

## Compatibility
ordinary profiles and financial history remain untouched.

## Testing
Required evidence: rollback rehearsal with bounded target time. The result is UNVERIFIED until a dated, redacted run is recorded.

## Rollback
select the prior release and reverse only scoped publication.

## Decision
Propose scoped rollback point per release edge and entitlement after the required evidence and approval gates; do not treat this ADR as authorization.

## Evidence
The master requirements and local design constraints are inputs only. Evidence addressing stale pointer can select an invalid dependency remains UNVERIFIED; live state, client behavior, timing, and rollback duration are unknown.
