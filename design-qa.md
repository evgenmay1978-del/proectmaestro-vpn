# Design QA — Home против выбранного эталона владельца

Эталон: `design/mobile-4d-references/04-owner-selected-home-2026-07-31.jpg` (591×1280,
приведён к app-owned вьюпорту 390×844; строки `y=0..49` — системная шторка Android, кодом
не воспроизводятся).

Превью: `build/phone-screen-sim/owner-home-{connected,connecting,disconnected}.png`,
доска сравнения `build/phone-screen-sim/owner-home-comparison.png`
(`python ops/phone-screen-sim.py`, exit 0, изображения 780×1688 = 390×844@2x, ничего не
обрезано).

⛔ Это симуляция по числам из Kotlin на подлинных ассетах репозитория, а НЕ скриншот:
глаз статичен (в приложении моргает, следит за пальцем), наклона/параллакса нет, атлас взят
в центральном свете. Поведение доказывают только CI и устройство.

## Что совпало

| Проверка | Результат |
|---|---|
| Порядок секций эталона | совпадает: титул+медальон → статус → активный протокол → телефон → пояснение → Telegram/МАКС/WhatsApp → дуга протоколов → «Купить подписку» → нижняя консоль |
| Первый вьюпорт 390×844 | вся первичная дека помещается: `primaryDeckBottom` = 839 ≤ 844, скролл не нужен |
| Титул | Playfair 46 sp = 253.2 dp в табличке эталона 254 dp (69→323); высота глифов 33 dp против 34 dp |
| Три состояния глаза | `ПОДКЛЮЧЕНО` — открыт, `ПОДКЛЮЧЕНИЕ` — полуоткрыт, `ОТКЛЮЧЕНО` — полностью закрыт, радужка не видна |
| Цели нажатия | ни одной ниже 48 dp: телефонная пилюля (орнамент 38 dp) и «Купить подписку» (45 dp) расширены вокруг того же центра |
| Чёрная плита | исчезла: полноэкранной подложки и градиентной маски в деке нет ни одной |
| Барабан | исчез: ни `rotationX`, ни `cameraDistance`, ни snap-fling, ни хаптик-тиков |

## P0 — блокирует полное совпадение (нужен арт, кодом не закрывается)

1. **Резной консоли и дуги эталона НЕТ в 15 слоях атласа.** Ниже кольца мастер-холст —
   гладкое дерево с одной орнаментальной планкой у самого низа (проверено реконструкцией
   центрального света). На эталоне там: дуга-веер с шестью резными секторами, бронзовые
   разделители с навершиями, изумруд в замке дуги и резная нижняя консоль с круглым
   бортиком под «Тест сети». Сейчас это заменено настоящими nine-patch `frame_button` —
   геометрия и порядок те же, но рельефа эталона нет.
   **Закрывается только новым слоем арта** (например `home_console_{l,c,r}.png` +
   `home_arc_{l,c,r}.png` в том же мастере 2160×4670 и тем же генератором
   `ops/mobile-4d-assets.py`). Выдумывать резьбу кодом не стал.

## P1 — расхождения, которые видно на доске

2. **Глаз шире внутреннего проёма кольца.** Веки достают до бронзы, на эталоне глаз вписан
   с запасом. Правка уже есть, но НЕ в этой ветке: `00e47a3` (клип по бронзовому кольцу
   вместо ужимания слоя) + сторож `c384ec6` живут в `feat/mobile-4d-redesign`, которой в
   `codex/mobile-4d-interface` нет. Решение о переносе — за владельцем.
3. **Центр медальона на 8.9 dp ниже эталона.** `heroTranslationY = −58` даёт центр
   кольца 267.4 dp против 258.5 dp у эталона. В допуске теста (`−58 ± 10`), поэтому число
   из `d60b6b0` не трогал; если владелец хочет точнее — `−67`.
4. **Секторов семь, а не шесть.** Владелец 31.07 отдельно потребовал WDTT (`vk-turn`) в
   меню; на эталоне его нет. Дуга ужимает боковой отступ (15 → 13 dp), чтобы седьмой
   сектор не увёл плитку ниже 48 dp. «NAIVEPROXY» при этом переносится на две строки
   (`NAIVE / PROXY`) — на эталоне подпись выходит за плитку прямо на резьбу, кодом так
   нельзя.

## P2 — отмечено, менять не стал

5. **Иконки контактов на эталоне перепутаны:** у плитки с подписью «МАКС» нарисован глиф
   WhatsApp, а у плитки «WhatsApp» — обычный «пузырь» сообщения. В коде взяты
   Material-иконки Send / Forum / Chat, а ссылки — по контракту плана: `t.me/wapmixx`,
   `max.ru`, `wa.me/79778116564`. Если это не опечатка арта — скажите, поменяю глифы.
6. **Плитки — рамка nine-patch, а не резная плита с угловым орнаментом.** Тот же
   ограничитель, что и P0: карточного арта в репозитории нет.
7. **Цвет статуса в состоянии «ПОДКЛЮЧЕНИЕ».** На эталоне такого состояния нет. Красная
   точка над словом «ПОДКЛЮЧЕНИЕ» — ярлык, который врёт (тот же класс дефекта, что
   «Загрузка…» над установкой обновления на ТВ), поэтому промежуточное состояние получило
   оранжевый цвет, а не цвет отказа.
8. **`PhoneStatusRow` в `TvHomeScreen.kt` остался мёртвым кодом.** Дека рисует статус сама,
   по границам эталона: у `PhoneStatusRow` своя вертикаль (padding 6 + spacer 8), и строка
   протокола уезжала на 398–418 dp — под телефонную пилюлю, чья цель нажатия начинается с
   402 dp. Удалить его нельзя: файл под нулевым TV-диффом. Нужна отдельная санкция
   владельца на правку `TvHomeScreen.kt`.

## Итог

**final result: blocked** — по пункту P0. Структура, порядок, геометрия, состояния глаза и
цели нажатия эталону соответствуют; резьба нижней половины требует нового арта.
Показываю превью владельцу и НЕ трачу GitHub CI на APK до его решения.
