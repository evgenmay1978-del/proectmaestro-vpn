## 2. Как проверить, что всё живо (быстрый чек-лист)
```bash
# на S1
systemctl --failed --no-legend | wc -l                      # ждём 0
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18910/healthz        # 200
systemctl list-timers 'maestro-*' --no-pager | head          # все таймеры с NEXT
journalctl -u maestro-rqlite-retention -n 5 --no-pager       # последний отчёт ретенции
journalctl -u maestro-rqlite-backup -n 3 --no-pager           # последний бэкап
tail -n 5 /var/log/maestro-panel-watchdog.log                 # только FAIL/рестарты
# размер базы и задержка rqlite (strong)
# (см. INCIDENT-2026-09-19-rqlite.md § «Полезные факты»)
```

## 3. Пороги и тревоги
- БД > 600 МБ → ретенция запускает `VACUUM`; БД > 800 МБ — повод разобраться, что пишет так много.
- Панель не отвечает 10 минут → сторож перезапускает; если и после этого нет — владельцу придёт уведомление.
- rqlite strong > 2 с или панель в цикле `schema unavailable` → смотреть `INCIDENT-2026-09-19-rqlite.md`.

## 4. Открытый вопрос: `/account/whitelist-runtime` → 503
Приложение (все клиенты) периодически опрашивает `GET /account/whitelist-runtime` и получает
`503 {"error":"unavailable"}`. Причина не в сбое: в конфиге панели выключен **whitelist-сайдкар**
(`MAESTRO_WHITELIST_SIDECAR_ENABLE=0`), поэтому `WhiteListPublicationSource = nil`, и нативный runtime-вид
честно отвечает «недоступно». Этот механизм — старая схема «exit-маршрутов через сайдкар-агентов»,
которую заменил flat-CDN (`/cdn-sub/` + метры origin’ов). Клиенты при этом работают: подписка `/cdn-sub/`
отдаётся и трафик идёт.
Варианты (нужно решение владельца):
1. оставить как есть (приложение само уходит на `/cdn-sub/`);
2. включить сайдкар обратно (`MAESTRO_WHITELIST_SIDECAR_ENABLE=1` + агенты на узлах) — вернёт старый контур,
   который 18.09 перегружал панель;
3. реализовать `WhiteListNativeRuntime` поверх flat-CDN-нод (профили из `flat-cdn-node.json` + гейт по ГБ) —
   тогда приложение получит «белые списки» нативно, без 503 и без сайдкара. Это доработка кода панели.

## 5. ЗАКРЫТО 20.09: `/account/whitelist-runtime` → 200 (вместо 503)

**Было:** приложение опрашивало ручку каждые ~3 секунды и получало `503 {"error":"unavailable"}`,
потому что `WhiteListPublicationSource == nil` (сайдкар выключен вместе с переходом на flat-CDN).
В логах nginx это давало постоянные 5xx, а приложение крутило retry-цикл.

**Стало (билд 7aad916c):** добавлен `flatCDNNativeRuntime` — нативный runtime-вид собирается из **тех же
flat-CDN нод**, что и подписка `/cdn-sub/`:
- гейт тот же: активная обычная подписка + положительный баланс купленных ГБ (`flatCDNEntitlement`);
- профили: `route_id=flat-cdn-N`, `label` (страна), `address/port/server_name/host/path`,
  `client_id` = per-customer UUID (HMAC), `encryption` = клиентское шифрование ноды;
- окно свежести: `issued_at_unix = now`, `fresh_until_unix = now + 4s`, `projection_version/desired_generation = 1`;
- при просроченной подписке или нулевом балансе — **403** (как и раньше), при неизвестном токене — 404.

Проверено: с телефона (как приложение) `GET https://wapmixx.ru:8911/account/whitelist-runtime` → **200 (8378 Б)**,
4 профиля 🇪🇸🇨🇿🇳🇱🇩🇪. В логе nginx после деплоя — **один запрос 200 и тишина**: приложение приняло ответ и
перестало опрашивать (раньше шло по 503 каждые 3 с). Подписки `/sub/` и `/cdn-sub/` — по-прежнему 200.

Файлы: `backend/internal/api/controlplane_whitelist_native.go` (фолбэк в обработчике),
`backend/internal/api/controlplane_flat_cdn.go` (сам вид). Деплой: `panel-candidate-7aad916c`.

## 9. Добавлен узел «Авто» в CDN-подписку (20.09, билд dfb1aae6)
Владелец: «на CDN пропал автовыбор сервера как на обычном VPN». Причина: CDN-подписка отдавалась как
массив из 4 отдельных xray-конфигов (по одному на страну), а авто-узел в обычной подписке строится
функцией subgen `whiteListAutoXrayJSONConfig` (leastPing-балансировщик + burst observatory) — в CDN-ветке
он не вызывался. Комбинированный рендерер `WhiteListCombinedXrayJSONSubscription` использовать нельзя:
он отвергает одинаковые client id, а в flat-CDN у всех нод один per-customer UUID.

Сделано:
- в `backend/internal/subgen/xray_json.go` добавлена экспортированная обёртка
  **`WhiteListAutoXrayJSONConfig(rendered []byte) ([]byte, error)`** — собирает авто-конфиг по уже
  отрендеренным per-node конфигам и ставит его первым;
- в `flatCDNXrayDocument` (`controlplane_flat_cdn.go`) результат оборачивается этой функцией;
  если авто-конфиг не собрался — подписка отдаётся без него (узлы важнее), в лог пишется причина.

Проверено:
- `/cdn-sub/<token>` теперь **5 конфигов**: `🇪🇺 ⚡ Авто` (outbounds proxy-1..4 + balancer leastPing)
  и 4 страны;
- в приложении (INCY) после обновления подписки в блоке «MaestroVPN VPN + CDN» появился
  **⚡ Авто — 278 мс**, ниже 🇪🇸 279 / 🇨🇿 231 мс и остальные страны — как в обычном VPN;
- `/sub/`, `/cdn-sub/`, `/account/whitelist-runtime` — все 200.

Примечание: «Авто» выразим только в JSON-конфиге xray (как и в обычной подписке); в формате ссылок
(`?format=links`) остаются 4 ссылки — это ограничение самого формата.
