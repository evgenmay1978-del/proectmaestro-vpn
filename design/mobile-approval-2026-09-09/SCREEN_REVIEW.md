# MaestroVPN — экраны на согласование

Статус: реализация разрешена. Ниже сохранён разбор исходных дефектов. В кандидат160 внесены мобильные страницы, общие исходные рамки, отдельные состояния баланса/сети, привязка продления к выбранному аккаунту, восстановление счёта и форматы подписок. Следующий шаг — GitHub-компиляция и реальные снимки APK. Серверный CDN и платежи не менялись. OTA159 остановлена.

Единственный образец оформления: `../mobile-4d-references/12-approved-mobile-home-2026-09-09.png`. Дерево, прямоугольные резные золотые панели, растительный периметр, изумрудные акценты. Глаз — из `11-natural-emerald-eye-2026-09-09.png`. Никаких новых овальных плашек, фоновых прямоугольников вокруг декора или текста на орнаменте. Декоративные края и внутренние отступы должны учитываться отдельно. Текст, цифры, флаги и состояние соединения рисуются интерфейсом, а не запекаются в текстуру. Числа 29 дней и 9,8 ГБ на референсах — образец компоновки, не прочитанный баланс владельца.

## Подтверждённые в исходниках проблемы

1. **Пустой список CDN ошибочно ведёт к покупке.** `PhoneDashboard.kt`, блок `sheet == "cdn"`: `cdnTags.isEmpty()` показывает «Нужны мобильная сеть и активный пакет гигабайт» и кнопку бота. `WhiteListSelection.preview()` очищает список также при Wi-Fi и при отсутствии свежего runtime. Это не доказательство отсутствия покупки. `PhoneWhiteListBalance.kt` отдельно получает баланс и отдаёт экрану только строку, поэтому экран не разделяет entitlement, сеть и загрузку маршрутов. Автоматический переход в Telegram по одному нажатию переключателя в прочитанном PhoneDashboard не найден: сам переключатель открывает sheet, Telegram открывают `openBot()`/кнопки. Точный переход на устройстве владельца ещё не наблюдался; не выдавать обнаруженный дефект за полное воспроизведение.
2. **Выбор CDN зависит от обычной группы.** `SFANavigation.kt`, `onSelectProtocol`: вся ветка, включая `selectCdn`, обёрнута в `selectGroup?.let`. При отсутствии обычной группы нажатие CDN может ничего не сделать. CDN должен вызывать уже существующий `selectCdn()` независимо от наличия группы libbox; проверки допуска в WhiteListSelection/Session сохраняются.
3. **Продление может относиться не к выбранному аккаунту.** `BuyViewModel.buy()` берёт первый непустой токен из `ProfileManager.list()`, тогда как баланс использует `Settings.selectedProfile`. Для нескольких импортированных подписок возможен неверный аккаунт продления. Все действия должны использовать один выбранный аккаунт и явно показывать его логин перед оплатой.
4. **Статус заказа теряется при уничтожении ViewModel.** `BuyViewModel.orderId` хранится только в памяти. Текущая форма после сетевой ошибки не должна подталкивать к повторной оплате. Нужно восстановление существующего заказа и отдельные состояния ожидания оплаты, подтверждения владельцем, обновления подписки и завершения. «Я оплатил» означает заявку, не выдачу доступа.
5. **Названия серверов слишком общие.** `phoneServerLabel()` превращает обычные теги в «Сервер · VLESS» и аналоги. На экране нужны страна/флаг из данных существующей подписки. Не назначать выдуманные страны или задержки.
6. **Выдача другим приложениям отстаёт от требуемого интерфейса.** `IosKaringDialog.kt` содержит Android/iPhone и `app=karing`; отдельных вариантов Happ/Incy в этом диалоге нет. Макет с выбором приложений — предлагаемое исправление, не уже работающая функция. Использовать существующие форматы сервиса, не создавать конвертер-обёртку.
7. **Настройки визуально неоднородны.** Главная открывает промежуточный settings-sheet, затем отдельный экран настроек. Некоторые дочерние страницы используют MobilePremiumShell, другие FantasyScreenBackground, AppSettings использует обычные Material ListItem. Нужен один комплект одобренных рам/полей/диалогов на всех телефонных страницах. TV-ветки сохраняются.

Это анализ текущего исходного кода, а не прогон всех сценариев на устройстве. Сборки и тесты в этой фазе не запускаются.

## Пункты и правильные действия

| Экран / пункт | Результат действия | Состояния и ограничения |
|---|---|---|
| Главная: глаз | Подключение/отключение выбранного режима через существующий DashboardViewModel | Подключение, подключено, отключено, ошибка; зелёный только после реального Started |
| Ввести логин | Единственный вход, выбор/обновление своей подписки | Сохранить существующий оплаченный профиль при ошибке; второй вход для CDN не нужен |
| Telegram-бот | Открыть существующего бота по явному нажатию | Не использовать как обработчик ошибок подключения |
| VPN: дни | Реальный срок выбранного аккаунта | Загрузка/временно недоступно/истекла; null не равен нулю |
| CDN: остаток | Реальные доступные, оплаченные и замороженные ГБ того же аккаунта | Ошибка связи не обнуляет покупку; последнее значение подписать как сохранённое, если показываем |
| Обычный VPN | Выбрать обычный профиль, без расходования CDN | Платные CDN-узлы не попадают в обычный автовыбор |
| CDN, пакет активен | Выбор CDN-сервера и подключение при действующем допуске | Покупка не требуется; никаких исключений по «логину хозяина» |
| CDN, Wi-Fi | Объяснить ограничение и предложить обычный VPN | Сохранить видимые ГБ; на мобильной сети CDN включается вручную |
| CDN, ошибка загрузки | Понятная причина и «Повторить» | Не открывать покупку или бота автоматически |
| CDN, подтверждённый нулевой остаток | Показать 0 ГБ и «Купить ГБ» | Только по полученному состоянию счёта, не по пустому списку |
| CDN, VPN истёк | Показать замороженные оплаченные ГБ и «Продлить VPN» | Не продавать второй раз уже купленные ГБ |
| Серверы | Страны, флаги, обычные/CDN раздельно, выбранный узел | Не показывать непроверенный ping как живой; обновление списка отдельным действием |
| Подписка | Логин, срок VPN, остаток CDN, действия с этим аккаунтом | Активный пакет и покупка разделены |
| Продлить VPN | Реальный каталог → заказ для выбранного аккаунта → СБП → подтверждение → обновление | Цена и сроки из backend; старую схему подтверждения оплаты сохранить |
| Купить ГБ | Существующий CDN-кабинет/бот по явному действию | Показать пакет/цену/счёт; пополнение после подтверждения сервиса |
| Пробный доступ | Существующий trial, форма имени, выдача после успеха | Не заменять уже оплаченный аккаунт без явного выбора |
| Подключить устройство | Выбор клиента/типа подписки, корректная ссылка/QR | Только текущая подписка; device-id получателя формируется на получателе |
| Сканировать QR | Разрешение камеры → сканирование → проверка → импорт | Отмена и отказ в разрешении возвращают на прежний экран |
| Приложения и VPN | Выбор приложений, поиск, явное сохранение/применение | Сохранить include/exclude и текущий безопасный порядок переподключения |
| Поддержка | Открыть существующий контакт по явному нажатию | Без автоматической отправки сообщений/журналов |
| Обновление приложения | Текущая версия, проверка, загрузка, системная установка | Существующая подпись/updater; не обещать принудительную установку всем |

## Остальные существующие страницы

Все перечисленные ниже маршруты остаются доступны. Это общий визуальный контракт дочерних экранов: тот же фон/периметр, заголовок и «Назад», прямоугольные панели, безопасные отступы, читаемые значения, единый вид полей/переключателей/ошибок. Не переносить крупный глаз на технические страницы и не добавлять новый уровень меню для каждого пункта.

| Существующая страница | Размещение и поведение при переносе оформления |
|---|---|
| `settings/app` | Версия, уведомления, язык, кэш, обновления; системные разрешения через Android, без изменения выбора пользователя |
| `settings/core` | Версия ядра и данные; служебные/разрушительные действия не превращать в обычную кнопку главной |
| `settings/service` | Режим сервиса, bypass и доступные текущие опции; показывать необходимость переподключения |
| `settings/profile_override` и `/manage` | Правила выбранного профиля и приложения; тот же аккаунт/профиль, без скрытого сброса |
| `settings/remote_control`, `/new`, `/edit/{id}` | Список и формы существующего удалённого управления; настройки не применять к другому устройству молча |
| `settings/fdroid_mirror` | Выбор существующего источника; без добавления новых зеркал |
| Новый/редактируемый профиль, содержимое, выбор иконки | Единые формы и подтверждения; секреты не показывать в обзорных референсах |
| Журнал | Читаемая моноширинная область внутри рамки; копирование/отправка только по явному действию |
| Диалоги оплаты, ошибки, обновления, QR, выборы | Общий фон и рамка, понятное действие и отмена; без стандартных белых/синих вставок |

## Объём следующей реализации после одобрения

Перенести одобренные исходные изображения без растяжения орнамента и без запечённого текста; связать существующие действия с достоверными состояниями выбранного аккаунта. Исправить найденные ветки локально, не перестраивать серверный CDN и платежную систему. Затем необходимая подписанная сборка только GitHub и показ настоящего приложения перед очередной рассылкой. Никаких новых тестов или тестового CI без отдельного указания.
