## 4. Самое важное: что ещё НЕ решено в клиенте

Стабильная работа самого CDN-туннеля на телефоне НЕ доказана. Исправления баланса и сохранения названий не продлевают действующую сессию. Не закрывать задачу по неизчезающему меню, одной странице, статусу active, сборке или CI.

Путь текущей реализации в `app/src/main/java/com/maestrovpn/tv/`:

1. `whitelist/WhiteListRuntime.kt`, `WhiteListRuntimeClient.fetchResult()`:
   - жёсткий предел3000 мс на каждую HTTP-попытку;
   - сначала `/account/whitelist-runtime`, затем фиксированный CDN fallback при транспортной ошибке/5xx;
   - две последовательные попытки могут занять около 6 с;
   - `parse()` принимает descriptor со сроком только1–5 с и привязывает deadline к началу запроса, вычитая время получения ответа.
2. `compose/screen/dashboard/groups/GroupsViewModel.kt`:
   - отдельный preview-fetch после каждого ответа с паузой 1 с, в том числе при активной CDN-сессии;
   - `selectCdnFresh()` делает свежий запрос после нажатия;
   - после него `WhiteListSession.prepare()` делает ещё один самостоятельный запрос.
3. `whitelist/WhiteListSession.kt`, `prepare()`:
   - получает runtime, выполняет DNS с пределом 1 с;
   - запускает native engine и повторно проверяет оставшийся допуск;
   - renewal ожидает `remaining - lastFetchMs - 250`, не более1000 мс;
   - один `fresh == null` немедленно вызывает `expire()`/nativeStop, даже если старый permit ещё имеет остаток времени;
   - смена generation/material/account/network или истечение deadline также закрывают сессию;
   - `armExpiry()` отдельно обеспечивает остановку по абсолютному deadline.
4. `whitelist/WhiteListSelection.kt`:
   - Ready/Denied/Unavailable сохраняют только названия при временной ошибке для того же аккаунта/мобильной сети;
   - при этом `previewDeadline=0`; свежая проверка перед подключением остаётся обязательной;
   - это защита отображения, не исправление реального обрыва.
5. `whitelist/WhiteListWatchdog.kt` с интервалами 25–35 с не является вызывающимся production-механизмом этой сессии. Не расследовать его вместо WhiteListSession.
6. `whitelist/XhttpNative.kt`, `WhiteListConfig.kt`, `bg/BoxService.kt` — существующий запуск native Xray внутри единственного VPNService. Не добавлять второй VPNService и не убирать protect/bindSocket.

Наблюдение13.09: прямой запрос native runtime с Windows занял2,938 с; ответ имел окно 4 с. Через системный прокси того же компьютера были 7–8 с. Это не измерение мобильного оператора. Гипотеза для проверки: короткое окно, последовательные запросы и немедленное закрытие при одной неудаче оставляют слишком мало времени для обновления. Не объявлять гипотезу подтверждённой причиной на телефоне без его лога/воспроизведения.
