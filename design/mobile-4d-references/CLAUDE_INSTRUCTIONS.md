# Инструкция Claude: мобильный 4D-интерфейс MaestroVPN

## Директива владельца

Мобильный интерфейс нужно пересобрать начисто по PNG-референсам из этой папки.
Запрещено накладывать новый дизайн поверх существующего дерева Compose,
оборачивать старые экраны дополнительными фонами/рамками или оставлять старые
полноэкранные слои невидимыми под новыми. Именно такое наслаивание уже привело к
избыточной глубине дерева и непредсказуемой геометрии.

## Сначала — инвентаризация, потом — код

Перед изменениями:

1. Прочитай все файлы в `design/mobile-4d-references/`.
2. Сопоставь каждый показанный экран с текущим route, composable, ViewModel,
   callback и ресурсом.
3. Отдельно составь список:
   - мобильных компонентов и ассетов, которые будут заменены;
   - общих компонентов и ассетов, используемых также ТВ;
   - TV-only файлов и веток, которые запрещено менять.
4. Покажи владельцу таблицу экранов и план удаления старого мобильного UI.
5. Не начинай реализацию, пока владелец не подтвердит весь набор экранов.

## Чистая архитектура мобильного экрана

Каждый новый телефонный экран строится из понятных концептуальных слоёв:

1. один фон;
2. один декоративный слой рамки/рельефа;
3. один hero-слой, если на экране есть живой глаз;
4. один слой интерактивного контента;
5. один временный overlay только для настоящего диалога, меню или системного
   состояния.

Не создавать несколько полноэкранных `Box`, `Image`, градиентов и масок,
дублирующих одну и ту же роль. Не держать старый экран под новым. Не прятать
старое дерево через `alpha = 0`, `visible = false`, clipping или перекрывающую
картинку.

Повторяемые рамки, кнопки, панели, поля и состояния должны идти через один
мобильный набор компонентов, а не копироваться в каждом экране.

## Удаление старого мобильного UI

После переноса каждого экрана:

- удалить заменённые mobile-only composable, модификаторы, маски и ресурсы;
- удалить мёртвые ветки, старые preview и дублирующие компоненты;
- удалить неиспользуемые импорты и ссылки;
- доказать поиском по репозиторию, что старые символы и ресурсы больше не
  используются;
- не удалять общий ресурс, пока не доказано, что его не использует ТВ.

Не делать массовое удаление «по названию». Сначала проверить все call sites и
resource references.

## ТВ — строго только чтение

Не изменять:

- TV-компоновку и TV-only composable;
- D-pad, focus, Back и восстановление фокуса;
- TV-геометрию, размеры и ассеты;
- TV-ветки `isTv`;
- TV screenshot/simulator golden reference;
- поведение универсального APK на телевизоре.

Если мобильный и TV код сейчас общий, сначала вынеси новый mobile-only компонент
за существующий runtime gate. Не «улучшай заодно» общую или TV-ветку.

## Обязательные визуальные состояния глаза

- `ОТКЛЮЧЕНО`: глаз полностью закрыт; радужка и зрачок не видны.
- `ПОДКЛЮЧЕНИЕ`: глаз частично открывается; свечение нарастает.
- `ПОДКЛЮЧЕНО`: глаз полностью открыт; сохранены моргание, взгляд и реакция на
  касание.
- Ошибка подключения: глаз закрывается или тревожно прищуривается, но состояние
  должно отличаться от обычного подключения.

Эти состояния должны следовать реальному состоянию VPN, а не декоративному
таймеру.

## Что сохранить

- текущие routes, ViewModel, callback, API, VPN-сервис, профили и оплату;
- существующие тексты и порядок данных, если владелец не утвердил изменение;
- тёмное дерево, бронзовую резьбу, изумрудный глаз и золотую типографику;
- минимум 48 dp для интерактивных целей;
- читаемость при увеличенном системном шрифте;
- скролл на коротких телефонах и компактную компоновку в landscape.

## Запрещено

- менять backend, API или VPN-runtime ради интерфейса;
- менять ТВ-версию;
- делать OTA-релиз или merge в `main` без отдельного разрешения владельца;
- считать PNG из ImageGen готовым ассетом без адаптации и проверки;
- добавлять новый функционал, которого нет в маршрутах и коде;
- оставлять заменённый мобильный UI «на всякий случай».

## Проверка до передачи

Claude должна предоставить:

1. список изменённых и удалённых mobile-only файлов;
2. подтверждение, что TV-файлы и TV-ветки не менялись;
3. до/после для всех экранов из этой папки;
4. доказательство состояний закрытого/открывающегося/открытого глаза;
5. проверку портрета, landscape, короткого экрана и увеличенного шрифта;
6. Android build и unit tests из проектного workflow;
7. отдельную ручную проверку APK на физическом телефоне;
8. финальный поиск мёртвых mobile-only символов и ресурсов;
9. финальный `git diff`, в котором нет backend, TV, release и OTA-файлов.
