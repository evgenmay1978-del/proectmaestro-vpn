# ADR-0016 — gated canary progression

Status: proposed. Conservative target only; no deployment, audit result or measurement is claimed.

## Topic-specific target
gated canary progression

## Problem
Move from isolated to internal then regional canary.

## Constraints
Real users require approval and rollback evidence. Four independently reconciled Data-plane Instances remain the target; secrets and sensitive owner context stay outside derivative artifacts.

## Alternatives
Immediate cutover; gated canary; indefinite test.

## Trade-offs
The selected target adds explicit evidence and rollback work but contains blast radius; a shortcut would couple unknown semantics to ordinary VPN.

## Risks
Unknown upstream/client behaviour, stale inventory and configuration drift can invalidate assumptions; these unknowns block production use.

## Compatibility
CDN publication is additive for ACTIVE entitlement and explicit preset only; ordinary nodes and existing accounts stay unchanged.

## Testing
Require source-linked isolated validation plus the named transport/subscription/metering evidence before a canary; record redacted release/checksum and result.

## Rollback
Retain a prior immutable release and reverse only the scoped edge/entitlement/release; preserve ordinary access and financial history.

## Decision
Adopt **gated canary progression** only after the listed evidence and owner gates.

## Evidence
MASTER constraints and ADR map are inputs. Read-only audit, client compatibility and live evidence remain UNVERIFIED until separately recorded.
