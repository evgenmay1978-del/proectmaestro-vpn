# Проверки функций ботов

Запускать только по разрешению владельца, в существующем Python venv соответствующего сервера. Скрипты не запускают polling, используют отдельные временные SQLite и фиктивных клиентов/Telegram. В функциональных проверках реальные сетевые подключения блокируются. Импортируется установленный код; пути соответствуют S1 /root/vpn_bot и S2 /opt/vpn_bot. Действующие .env/клиентские БД не изменяются. S2 fixture содержит sub_url как действующая база.

s1_functions.py: клиентские и админские сценарии, оплата/повтор/отказ, фото, QR, тарифы, тестовая SQLite-копия/ZIP, дни/дата/блокировка.
s2_functions.py: аналогичные функции Naive, создание/удаление, привязка, рассылка только в фиктивный transport, отказы и повторное подтверждение.
cdn_ack.py: намеренно зависший ACK; обработка оплаты и подтверждения продолжается, повтор не создаёт новое начисление. Таймауты здесь намеренные.

Это проверки обработчиков с изолированными зависимостями. Они не заменяют реальный Telegram→API→начисление; отдельные живые CDN-заявки и их результаты описаны в docs/telegram-bots/INCIDENT_PAYMENT_2026-09-11.md.
