## Origin TCP / состояние наблюдения

Два ограниченных AF_PACKET наблюдения только TCP 28080/28081: в памяти максимум 192 bytes пакета; сохранялись длины, время, flags, sequence и хеши временных flow/session, не payload или URL. Оба завершены, dropped=0. У активного потока Xray → nginx → CDN данные продолжались за 60 с. В sampled ss RTT ~39–50 ms, MSS 1398, PMTU 1500, признаков устойчивых retrans в этом окне не получено. MTU/потеря пакетов не установлены как причина, менять MSS по этим данным нельзя.

Один прямой SSH к S4 со станции дал connection timeout; альтернативный существующий jump через S1 с теми же ключами/host verification сработал. Это отличие путей, не доказательство падения S4.

Временные клиентские процессы остановлены; root-only временные client.json, response и debug log удалены в finally. Постоянные сторожа продолжают запись. Локальный воспроизводитель находится только в operational workspace ping-cdn-handoff/reproduce-cdn-owner.py, не содержит subscription tokens/UUID/ключей и не меняет production.

Крупная загрузка для самостоятельного достижения нулевого byte-credit пока не запускалась. Ночные шесть эпизодов исчерпания остаются данными сторожа из WATCHDOG_READOUT_2026-09-13.md operational workspace, а не новым результатом такого прогона.

## Готовые контроллеры: что действительно проверено

1. **Remnawave** — основной кандидат для отдельного CDN-контура. Открытый backend, REST API, пользователи/узлы, traffic limits и произвольные XHTTP extra в официальной SDK-модели. Это подтверждение возможностей, не наш live pass и не готовая безусловная миграция.
   - https://github.com/remnawave/backend
   - https://docs.rw/
   - https://docs.rw/learn-en/users/
   - https://github.com/remnawave/python-sdk/blob/production/remnawave/models/subscription.py
2. **Marzban** — открытая альтернатива: REST API, multiple nodes, ограничения трафика/сроков, изменяемая конфигурация Xray. Точный наш GET-body XHTTP/ML-KEM round-trip и интеграция с текущими балансами здесь не проверены.
   - https://github.com/Gozargah/Marzban
3. **3x-ui** уже используется для ordinary VPN. Современная версия поддерживает XHTTP/квоты/API, но официальный README/wiki предупреждает о personal-use/non-production назначении. Это не основание обновлять S4 или переносить CDN без отдельной схемы.
   - https://github.com/MHSanaei/3x-ui/wiki/

Ничего из найденных проектов не установлено. Закрытый matrixlegend-code/vpn-cdn-installer не рассматривается как проверенный готовый контроллер; прежний аудит уже показал отсутствие исходника.

## Предложение, ещё не согласованное

Если владелец выбирает готовую базу: отдельный Remnawave + стандартный Xray для CDN, с адаптером к нынешним оплатам/остаткам и сохранением обычных VPN и публичных subscription URLs. Сначала одна изолированная owner-конфигурация; перед переносом клиентов — реальное открытие сайтов, повторное подключение после idle и загрузка больше прежнего 16-MB окна, проверка учёта и подготовленный откат. Не переносить всех клиентов и не выключать существующий runtime по одному факту установки панели.

Самостоятельная перепись контроллера с нуля сейчас не обоснована преимуществом перед готовой базой. Смена контроллера также не доказана достаточной для устранения всех наблюдаемых транспортных отказов. Следующая развилка — согласование владельцем CDN-only схемы готового контроллера либо продолжение адресной локализации/исправления текущей реализации. Ошибка остаётся открытой.
