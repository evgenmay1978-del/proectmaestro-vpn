# Измеренный резерв допуска CDN

`MAESTRO_WHITELIST_RESERVE_FILE` — необязательный путь к локальному JSON-отчёту
для существующего rqlite collector. Сам параметр не включает collector,
публикацию подписок или реальные списания. Пустой параметр не создаёт provider;
обычный VPN и учёт уже полученных counters продолжают работать.

Отчёт — доверенный ввод оператора из реального canary, а не самостоятельное
доказательство измерений. Парсер не подтверждает качество выборки, задержку
revoke или готовность к платному запуску. Эти production gates остаются обязательными.
Нельзя подставлять тарифную скорость сервера, синтетический counter proof,
нулевой rate, отсутствующие counters или пример ниже вместо измерения.

## Формат

Ниже только истёкшая тестовая структура, **не production measurement**:

```json
{
  "schema_version": 1,
  "unit": "BYTES_PER_SECOND",
  "basis": "UPLINK_PLUS_DOWNLINK",
  "measurements": [
    {
      "exit_id": "exit-nl",
      "measured_p999_bytes_per_second": 3000000,
      "measured_at_unix": 2000000,
      "valid_until_unix": 2000020
    }
  ]
}
```

Для каждого разрешаемого exit нужен собственный результат. Rate — консервативный
p99.9 суммарных UP+DOWN bytes/s **одного аккаунта по всем активным Origin и его
одновременным устройствам**, не скорость одного направления/соединения/Origin.
Для общего отчёта значение должно покрывать допустимую canary-нагрузку аккаунта,
а не среднее по клиентам. Window, population, число samples, конфигурация fleet,
артефакт исходных измерений и обоснованный срок действия должны быть сохранены
в operational evidence до установки отчёта. Смена этих условий требует повторной
оценки; JSON-loader сам её не выполняет. Сроки и числа не генерируются из defaults.

Резерв рассчитывается существующим control-plane методом:
`max(10_000_000 bytes, measured_p999_bytes_per_second × 5 seconds)`.
Это условие допуска, не списание и не отрицательный баланс.

## Подключение без перезапуска обычного VPN

1. После действительных измерений сохранить отчёт как отдельный regular file,
   доступный panel-service для чтения, но не клиентам/ботам для записи.
   Рекомендуемый владелец root, группа panel-service, права0640; каталог не должен
   быть доступен для записи непривилегированным пользователям.
2. При штатной конфигурации rqlite panel задать `MAESTRO_WHITELIST_RESERVE_FILE`.
   Не менять существующий publication/collector flag до его rollout gates.
3. Обновлять отчёт атомарной заменой файла в том же защищённом каталоге.
   Collector перечитывает его один раз за pass, после authenticated observations
   и успешных debits. Продление отчёта не требует рестарта panel или обычного VPN.

Максимум64KiB. Неверная схема/единица/basis, неизвестные поля, повтор exit,
несколько JSON-документов, нулевой/overflow rate, будущая дата или истёкший срок
отклоняют отчёт целиком. Частичное содержимое не используется. Missing exit не
получает fallback от другого exit. Missing/invalid report не отменяет уже выполненный
учёт и не пропускает обязательный reconcile.

Кандидаты берутся из оплаченных enabled publications и credentials, а не из уже
managed `plan.Routes`: первый клиент должен получить admission до появления своего
managed user. Затем существующий `AuthorizeWhiteListMeteringAdmission` повторно
проверяет paid period, баланс, все Origin, exact receipts и неизменяемую историю.

Удаление отчёта прекращает новые authorizations/refresh. Уже записанные admission
leases живут только до своего `valid_until_unix` и остальных существующих gates;
удаление файла не является мгновенным admin revoke. Для немедленного отключения
клиента использовать существующий admin disable. Новый отчёт не обнуляет историю
first-observed и не возобновляет использованное grace.

Реального измеренного production-отчёта этим изменением не создано. До его получения,
live sampling/revoke canary и оставшихся accounting gates платный rollout — NO_GO.
