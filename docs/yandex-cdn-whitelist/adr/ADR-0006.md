# ADR-0006 — immutable release pointer

Status: proposed. Target-only; no deployment, audit result, measurement, or operational completion is claimed.

## Topic-specific target
immutable release pointer

## Problem
Choose a safe target for immutable release pointer without coupling it to ordinary VPN or claiming unobserved behavior.

## Constraints
The decision remains isolated, reversible, secret-free, and blocked from live use until its own evidence and same-turn approval gate exist.

## Alternatives
edit active config versus mutable bundle versus immutable release pointer.

## Trade-offs
release storage grows but auditability improves; this cost is accepted only if the isolation boundary is demonstrated.

## Risks
partial reconciliation can split selected versions; the risk remains an open blocker rather than an assumed success.

## Compatibility
older reconciler must reject unsupported release schema.

## Testing
Required evidence: selected checksum convergence on all target nodes. The result is UNVERIFIED until a dated, redacted run is recorded.

## Rollback
previous release pointer without editing releases.

## Decision
Propose immutable release pointer reconciled per node after the required evidence and approval gates; do not treat this ADR as authorization.

## Evidence
The master requirements and local design constraints are inputs only. Evidence addressing partial reconciliation can split selected versions remains UNVERIFIED; live state, client behavior, timing, and rollback duration are unknown.
