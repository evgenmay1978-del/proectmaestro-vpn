# Разделение «протокол» и «сервер» на телефонном Home

**Статус:** ждёт проверки владельцем
**Дата:** 2026-08-02
**Платформа:** ТОЛЬКО телефон (`PhoneHomeControlDeck.kt`). ТВ — отдельной задачей позже.
**Ветка кода:** `codex/mobile-4d-interface` (там живёт `PhoneHomeControlDeck.kt`; в `main` его нет)
**Связанные спеки:** `2026-08-01-mobile-4d-seven-sector-arc-console-design.md` (семисекторная дуга)

## 1. Задача

На главном экране в одном ряду смешаны два разных измерения:

- **чем** соединяться — VLESS, Hysteria2, AnyTLS, NaiveProxy;
- **через какой сервер** — `vless` (S1), `vless-s3` (S3), а с 02.08 ещё и `vless-s4` (S4).

Из-за этого один протокол выглядит как несколько разных, и **каждый новый сервер съедает слот**.
Слотов ровно семь (`ARC_SECTOR_CENTERS`, замерены по арту), и они уже кончились: у клиента с WDTT
сейчас получается восемь элементов при семи ячейках, а лишнее молча не отрисовывается
(`cells.getOrNull(index) ?: return@forEachIndexed` — краха нет, но плитка исчезает бесследно).

Задача владельца дословно: «не плодя кнопки».

## 2. Решение

Семь ячеек остаются семью — **арт НЕ перерисовывается**. Меняется только их содержимое:

| ячейка | было (спека 01.08) | становится |
|---|---|---|
| 1 | Auto | Auto |
| 2 | VLESS | **VLESS** — все серверы схлопнуты в один пункт |
| 3 | Hysteria2 | Hysteria2 |
| 4 | AnyTLS | AnyTLS |
| 5 | NaiveProxy | NaiveProxy |
| 6 | WDTT / VK-TURN | **Серверы** → экран выбора узла |
| 7 | OLC / TURN | **Ещё** → WDTT, olcRTC и прочее редкое |

⚠️ **Это сознательное отступление от состава, утверждённого в спеке 01.08.** Там ячейки 6 и 7 были
отданы WDTT и OLC. Геометрия, число ячеек и файлы арта не затрагиваются — меняются подписи, иконки
и обработчики нажатия, то есть только Kotlin.

**Главное свойство:** число ячеек перестаёт зависеть от числа серверов. S5, S6, S10 не меняют
главный экран вообще — они появляются внутри «Серверов».

## 3. Поведение

- **Тап по «VLESS»** — включить VLESS, автоматически выбрав сервер с наименьшей задержкой среди
  `vless*`. Это НЕ дубль «Авто»: «Авто» выбирает лучшее среди всех протоколов, «VLESS» — лучший
  сервер внутри VLESS.
- **Подпись под «VLESS»** — имя текущего сервера, чтобы выбор был виден без захода в экран.
- **Тап по «Серверы»** — переход на экран со списком узлов, задержками и ручным выбором.
- **Тап по «Ещё»** — список редких протоколов (WDTT, olcRTC). Недоступные показываются с замком, как
  сейчас (`locked = protocol == "olcrtc" && !hasOlcrtcCreds`).

## 4. Реализация

**Группировка — в приложении, НЕ в конфиге.** Это обязательное требование: вложенные селекторы на
стороне панели изменили бы конфиг у всех, включая пять клиентов ниже vc138, которые не обновляются.
Группировка в UI не трогает ни подписку, ни ядро, ни старые версии.

- `orderedHomeProtocols()` (`PhoneHomeControlDeck.kt:776`) перестаёт возвращать плоский список тегов
  и возвращает семь **позиций экрана**: пять протокольных, «Серверы», «Ещё».
- Схлопывание: теги, начинающиеся с `vless`, сводятся в одну позицию. Правило по префиксу, а не
  список — тогда S5/S6 подхватятся сами, без правки кода.
- Экран «Серверы» — переиспользуется существующий `GroupsCard` / `GroupsViewModel`
  (маршрут `Screen.Groups` уже есть в `SFANavigation.kt:273`). Он уже читает узлы из ядра и умеет
  `selectOutbound(groupTag, itemTag)` и `urlTest(groupTag)`. Новый экран НЕ пишем.
- Человеческие имена узлов вместо технических тегов. Нумерация **порядковая, по позиции в списке**,
  а не по внутреннему имени узла: `vless` → «Сервер 1», `vless-s3` → «Сервер 2», `vless-s4` →
  «Сервер 3». ⛔ Именно так, а не «1/3/4»: внутренний S2 несёт Hysteria2/Naive/AnyTLS и вообще не
  имеет VLESS, поэтому нумерация по именам узлов дала бы клиенту дырку («где Сервер 2?»).
  Запасной вариант: неизвестный тег показывается как есть — новый сервер никогда не даёт пустую
  подпись.
- «Ещё» — существующий `FantasyDialog` (стиль проекта уже задан), новый компонент не нужен.

## 5. Что НЕ меняется

- Конфиг подписки, `subgen`, ядро, формат `/sub` — ни байта.
- ТВ-экраны (`TvEskizHome.kt`, `TvHomeScreen.kt`) — вне этой задачи.
- Файлы арта `home_arc_*.png` и геометрия `ARC_SECTOR_CENTERS`.
- Поведение «Авто».

## 6. Проверка

1. Юнит-тест на `orderedHomeProtocols()`: при входе `[auto, vless, hysteria2, naive, anytls,
   vless-s3, vless-s4]` возвращается ровно 7 позиций, среди них одна VLESS, «Серверы» и «Ещё»;
   добавление восьмого и девятого `vless*` число позиций НЕ меняет.
2. Тест на схлопывание по префиксу: гипотетический `vless-s9` не создаёт новой позиции.
3. Тест проверяется падением (сломать схлопывание → тест обязан упасть).
4. Компайл-гейт `android-test.yml` на ветке — зелёный.
5. Владелец смотрит глазами на приборе: ни одна прежняя плитка не пропала, VLESS показывает имя
   текущего сервера, «Серверы» открывают список с пингами.

## 7. Крайний случай: у клиента нет ни WDTT, ни olcRTC

**Решение по умолчанию: «Ещё» показывается всегда**, редкие протоколы внутри — с замком. Это
повторяет уже принятое поведение для olcRTC (`locked` вместо скрытия) и держит расположение ячеек
одинаковым у всех клиентов, что важно при поддержке по телефону: «нажмите шестую слева» работает
для любого клиента.

Альтернатива (прятать «Ещё», оставляя шесть ячеек) отклонена: расположение ячеек начало бы зависеть
от набора протоколов, и владелец не мог бы вслепую подсказать клиенту, куда нажимать.

Пересмотреть можно после просмотра на приборе.
